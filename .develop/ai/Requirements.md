# DaemonMan 需求文档

## 1. 项目概述

### 1.1 项目名称
DaemonMan - 跨平台守护进程与服务管理系统

### 1.2 项目背景
开发一个类似于 Linux systemd 的跨平台守护进程/服务管理系统，使用 workflow 任务流和图形算法编排任务，支持依赖关系管理，并接管系统自启动应用的管理。

### 1.3 核心目标
- 提供类似 systemd 的服务管理功能，但跨平台支持
- 使用任务流编排处理服务依赖关系
- 提供直观的图形界面管理守护进程
- 支持系统自启动应用的管理和监控

## 2. 技术栈与架构

### 2.1 框架选择
- **主框架**: Tauri (v2.x)
- **后端语言**: Rust
- **前端语言**: TypeScript
- **前端框架**: Vue 3 + Composition API
- **样式方案**: Tailwind CSS (纯 class 方式，避免 CSS 文件)
- **构建工具**: pnpm

### 2.2 项目结构
```
$Workspace/daemon-man/
├── src-tauri/          # Rust 后端代码
│   ├── src/
│   │   ├── core/       # 核心业务逻辑
│   │   ├── service/    # 服务管理
│   │   ├── workflow/   # 工作流引擎
│   │   └── platform/   # 平台特定实现
│   └── Cargo.toml
├── src/               # 前端代码
│   ├── components/    # Vue 组件
│   ├── views/         # 页面视图
│   ├── stores/        # Pinia 状态管理
│   ├── locales/       # i18n 语言文件
│   ├── themes/        # 主题配置
│   └── utils/         # 工具函数
├── public/            # 静态资源
└── package.json
```

### 2.3 开发与调试
- **开发命令**: `pnpm tauri dev`
- **构建命令**: `pnpm tauri build`

## 3. 功能需求详细说明

### 3.1 系统托盘功能
#### 3.1.1 托盘图标
- 在系统托盘创建 DaemonMan 图标
- 图标应根据服务状态变化（正常/警告/错误）

#### 3.1.2 双击行为
- 双击托盘图标：显示/隐藏主窗口
- 窗口状态应持久化，下次启动时恢复上次状态

#### 3.1.3 右键菜单
```
右键菜单项：
├── 显示/隐藏主窗口
├── 暂停/恢复所有服务
├── 运行诊断工具
├── 查看运行日志
├── 分隔线
└── 退出 DaemonMan
```

### 3.2 主窗口布局
#### 3.2.1 整体结构
```
┌─────────────────────────────────────────────┐
│ 标题栏 (含窗口控制)                         │
├───────────┬─────────────────────────────────┤
│           │                                 │
│  导航栏   │           内容区域              │
│           │                                 │
│           │                                 │
├───────────┴─────────────────────────────────┤
│ 状态栏 (可选，根据设置显示)                 │
└─────────────────────────────────────────────┘
```

#### 3.2.2 导航栏项目
1. **主页** - 显示系统概览
2. **任务流视图** - 任务流管理界面
3. **服务列表** - 所有守护进程/服务列表
4. **启动项管理** - 系统自启动应用管理
5. **设置** - 程序设置

### 3.3 主页面板
#### 3.3.1 概览卡片
1. **系统状态卡片**
   - 运行中的服务数量
   - 失败的任务数量
   - 系统正常运行时间
   - CPU/内存使用率

2. **任务流概览卡片**
   - 最近运行的任务流列表（最多5个）
   - 每个任务流的运行状态
   - 快速操作按钮（运行/停止）

3. **自启动流程图卡片**
   - 当前自启动应用的依赖关系图
   - 实时运行状态显示
   - 执行完成后的折叠视图

#### 3.3.2 卡片布局
- 使用响应式网格布局
- 支持卡片拖拽重新排列
- 卡片可折叠/展开
- 暗色/亮色主题适配

### 3.4 任务流视图
#### 3.4.1 左侧任务流列表
- 树状结构展示所有任务流
- 支持按名称、状态、最近修改时间排序
- 搜索和筛选功能
- 右键菜单支持创建、删除、复制任务流

#### 3.4.2 右侧编辑区域
- **可视化编辑器**: 基于节点的流程图编辑
- **属性面板**: 节点/边的详细配置
- **工具栏**: 
  - 保存/另存为
  - 撤销/重做
  - 缩放控制
  - 运行/调试
- **依赖图算法可视化**: 实时显示依赖关系解析结果

#### 3.4.3 任务流特性
- 支持顺序、并行、条件分支
- 任务依赖关系自动检测和解析
- 错误处理和重试机制
- 任务超时设置
- 日志记录和追踪

### 3.5 设置面板
#### 3.5.1 设置分类
1. **常规设置**
   - 启动行为
   - 托盘图标设置
   - 语言选择

2. **外观设置**
   - 主题选择（明/暗）
   - 自定义颜色主题
   - 字体大小和界面缩放

3. **服务设置**
   - 默认服务启动超时
   - 失败重试策略
   - 日志保留策略

4. **任务流设置**
   - 默认执行超时
   - 并发控制设置
   - 缓存策略

5. **平台设置**
   - Windows 特定设置
   - Linux/macOS 预留设置
   - 配置文件位置管理

#### 3.5.2 设置项展示
- 使用 Tile List 布局
- 每个设置项包含：图标、标题、描述、控件
- 实时保存设置更改
- 支持设置导入/导出

### 3.6 主题与国际化
#### 3.6.1 主题系统
- 内置明/暗主题
- 支持用户自定义颜色主题
- 主题预览功能
- 主题导出/导入

#### 3.6.2 国际化支持
- 支持语言：英语、简体中文（后续扩展）
- 动态语言切换
- 日期/时间/数字格式本地化

## 4. 平台特定需求

### 4.1 Windows 平台
#### 4.1.1 安装类型识别
- 自动检测当前安装模式（所有用户/当前用户）
- 根据安装类型调整配置文件位置
- 权限管理适配

#### 4.1.2 配置文件管理
- 默认位置：`%USERPROFILE%\.daemon-man\`
- 支持软链接目录检测
- 配置文件格式：JSON with schema validation

#### 4.1.3 服务管理
- 使用 Windows Service Control Manager 集成
- 支持传统 Win32 服务
- 支持现代 Windows 服务

### 4.2 跨平台接口设计
```rust
// 平台抽象层示例
trait PlatformService {
    fn start_service(&self, name: &str) -> Result<ServiceHandle>;
    fn stop_service(&self, name: &str) -> Result<()>;
    fn list_services(&self) -> Result<Vec<ServiceInfo>>;
    fn install_autostart(&self, config: AutostartConfig) -> Result<()>;
}
```

## 5. 核心算法需求

### 5.1 依赖关系解析
- 使用有向无环图（DAG）算法
- 拓扑排序确定执行顺序
- 循环依赖检测和报告

### 5.2 任务调度
- 基于依赖关系的智能调度
- 并行任务优化
- 资源限制和优先级管理

### 5.3 错误处理
- 故障传递机制
- 优雅降级策略
- 恢复点设置和回滚

## 6. 非功能需求

### 6.1 性能要求
- 主界面加载时间 < 2秒
- 任务流渲染响应时间 < 100ms
- 服务状态更新延迟 < 500ms

### 6.2 稳定性
- 7x24小时不间断运行
- 内存泄漏监控和预防
- 异常崩溃恢复机制

### 6.3 安全性
- 配置文件加密存储选项
- 服务操作权限验证
- 防止恶意任务流执行

### 6.4 可维护性
- 详细的日志系统
- 远程诊断支持
- 自动更新机制

## 7. 开发约束

### 7.1 前端约束
- 使用纯 Tailwind CSS class，避免 `style` 标签和内联样式
- 组件使用 Composition API 编写
- 状态管理使用 Pinia
- 响应式设计，支持 1024x768 及以上分辨率

### 7.2 后端约束
- 异步编程使用 Tokio 运行时
- 错误处理使用 anyhow/thiserror
- 配置管理使用 serde

### 7.3 代码质量
- TypeScript 严格模式
- Rust clippy 检查
- 单元测试覆盖率 > 80%
- E2E 测试关键路径
